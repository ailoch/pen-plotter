# SVG-to-Gcode Pen Plotter

Converts an SVG drawing into G-code that drives a Bambu Lab P1S 3D printer as an XY pen plotter.

## Running

[`_Process.py`](_Process.py) is the entry point — prompts for SVG input and gcode output files, then runs:
1. **Parse** SVG → geometry model
2. **Stroke** — generate multi-pass strokes from each shape's stroke width/style
3. **Infill** — add concentric loops to fill interiors of shapes
4. **Drop raw geometry** — remove the now-unneeded parsed centerlines
5. **Route** — reorder paths to minimize travel distance
6. **Generate** — converts intenal geometry model to G-code (lines → G1, arcs → G2/G3)

All logic lives in `lib/`, importable for testing (no module-level side effects).

## Geometry Model

[`lib/geometry.py`](lib/geometry.py): `Segment` (Line/Arc/QuadraticBezier/CubicBezier) → `Path` (segments + `lineType: LineType`) → `PathObject` (Paths + Style + Transform + `overrides`, see Calibration) → `Document` (PathObjects). `lineType` lives on `Path`, not `Style`, because one `PathObject` mixes roles (stroke passes, infill loops, gap-fill strokes) once generation runs. It defaults to `RAW_GEOMETRY` — the parsed centerline, a *source* for stroke/fill rather than something ever drawn — which `lib/stroke.py`'s `dropRawGeometry` strips before routing.

`Style` carries stroke info (`strokeWidth`, `strokeColor`, `linejoin`/`linecap`/`miterlimit`, `dasharray`/`dashoffset`) rather than `lib/stroke.py`, because `lib/infill.py` needs `Style.dashPattern()` too (a dashed stroke doesn't cover the fill's outer band) and `stroke.py` already imports from `infill.py` — a helper on the stroke side would be circular. `strokeWidth`/`dasharray`/`dashoffset` share one length space and are scaled together by `PathObject.applyTransformations()`. svgelements has no dash support at all, so dash parsing is hand-rolled in `readStyle` and multiplied by the *cumulative* ancestor transform (not just the root viewport) to land in that same space.

Useful primitives: `Path.isFillable()` (encloses area — used to gate infill, distinct from `isClosed()`), `tessellate(tolerance, allowArcs)` (reduces to Line/Arc), `rotateTo()` (re-anchors closed paths for routing). On `Line`/`Arc`: `a @ b` (intersection), `tAtPoint(pt)`, and `subsegment(t0, t1)` (exact on Line/Arc only — a bezier has no closed-form sub-range, and both callers only ever see already-tessellated geometry).

## Key Pipeline Stages

**Parse** ([`lib/svgparse.py`](lib/svgparse.py)): `loadSvg` reads into an svgelements tree; `parseSvg` walks it into a `Document`. `Rect`/`Path`/`SimpleLine`/`Polyline`/`Polygon` share one branch (same Move/Line/Arc/Bezier vocabulary); `Circle`/`Ellipse` are handled separately since one `Arc` represents them exactly, vs. the 5 segments their own `segments()` would decompose into. `<use>` is unsupported. Visibility (`display`/`visibility`/`opacity`) is checked only on leaf shapes, not on groups, so a hidden group's visible descendants still get drawn if they override it. Rescale prompting (see Alignment & Scaling) happens before the parse timer starts.

**Stroke** ([`lib/stroke.py`](lib/stroke.py)): builds multi-pass concentric `STROKE` loops per stroked object, sharing pyclipper helpers with `lib/infill.py`. `numPasses = ceil(strokeWidth / fillSpacing)`, snapped to the nearest integer first so float noise can't add a spurious extra pass (and flip parity — see the comment at `_passCount`). Odd counts get an exact center pass (`deepcopy`, preserving arcs/beziers); either parity lands the outermost pass exactly at `strokeWidth/2`. A residue pass (shared with infill, see below) fills wedges a mitered/beveled corner or tight curve leaves between passes.

**Butt caps** would otherwise land every pass's turnaround on the stroke's own end plane — the passes re-ink that one line, and each crossing's ±`fillSpacing/2` of ink overruns the end. So each pass's cap is set back by its own depth into the band (`strokeWidth/2 - delta`), staircasing the ends the way an inset of the band would and leaving the end behaving exactly like the sides. Falls back to a single centerline pass if pyclipper is missing or `generateStroke` is off. Must run before `generateInfill`, since a stroked object's fill inset depends on `strokeWidth`/`linejoin`.

**Dashes**: `style.dashPattern()` splits `RAW_GEOMETRY` into inked pieces (`_applyDash`) before anything else in Stroke runs, via an exact arc-length walk over already-tessellated (Line/circular-Arc only) geometry — dashing raw beziers would need a numerical arc-length inversion per cut.

**One-sided dashes**: a dashed stroke over a fill draws only its outward half — the fill already covers the inner half continuously, since SVG paints fill straight across dash gaps — by diffing the dash band against the fill region and handing the outward remainder to the same ring-tiling `_fillRegion` infill uses. `generateInfill`'s matching half is excluding a dashed stroke from its own outer inset (see Infill). Falls back to two-sided dashes whenever nothing else would cover the inner half (no fill, `fillSpacing <= 0`, a resolve failure).

**Infill** ([`lib/infill.py`](lib/infill.py)): resolves the fill region under `fill-rule`, then tiles concentric rings inward, drawing `GAP_INFILL` centerline strokes over whatever each ring's ink misses (`_fillRegion`) — coverage is complete by construction, not a global post-pass. Gated on `isFillable()` (a permissive shoelace-based check; pyclipper resolves the real fill-rule geometry afterward), not `isClosed()`. Ring `k` sits at `firstDelta + k*spacing`; `firstDelta` is `penWidth/2` (not the more conservative `spacing/2` used for interior tiling) so the pen's real ink reaches the true boundary exactly, or `strokeWidth/2 + penWidth/2` when a (non-dashed) stroke already inks the outer band.

Per-ring residue is what a ring's own ink band misses inside its annulus — acute wedges, and thin features (a stem narrower than `spacing`) that leave no closed loop at all. A thin residue piece (≤`spacing` wide) is drawn as its **medial axis** — a Voronoi skeleton of its resampled boundary, pruned of sub-`spacing/2` spurs and decomposed straight through junctions so one spine stays one stroke — as open `GAP_INFILL` centerlines; a genuinely wide piece falls back to concentric loops. `lib/stroke.py` shares this same residue routine for its whole stroke band.

Because gap fill is drawn as centerlines, its ink reaches `penWidth/2` either side — enough to spill past the true outer boundary if drawn right up to it. So residue is clipped to a `keepIn` region (the boundary already pulled `penWidth/2` in) before any skeleton is taken; a tip or sliver too narrow to hold a centerline that far in is left bare rather than overinked. `tests/test_coverage.py`'s `testGapInfillInksNothingOutsideTheShape` pins this; `testNothingLeftUninked` opens its target region by `penWidth/2` to match.

Overcoverage is fine (a doubled pass is invisible on paper); the invariant is that nothing wider than the pen is left uninked. Interior coverage width (ring pitch, residue detection) is always `fillSpacing`, never `penWidth` — `firstDelta` is the one exception, since it places a boundary the pen's real ink must reach exactly rather than measuring interior coverage.

**Route** ([`lib/route.py`](lib/route.py)): nearest-neighbor + 2-opt + anchor-optimization + rendezvous move reorders subpaths within each object, then objects themselves, to minimize pen travel. `_travelCost` folds in an estimated pen lift/lower time so the router's cost model matches the real pen-up move `lib/plot.py` emits, including the `shortTravelThresholds` rule that keeps a short hop pen-down. Runs after `dropRawGeometry`, so every item it sees has a real drawn role.

**Generate** ([`lib/plot.py`](lib/plot.py)): tessellates each path to Line/Arc and emits G1/G2/G3, interspersed with travel moves. Every segment is first clipped to the canvas bounds in nozzle space (`_splitAtBounds`, via `Line`/`Arc.__matmul__` intersections and `tAtPoint`/`subsegment`) — a piece landing outside is either dropped silently or drawn as `LineType.INVALID`, per `showOutOfBounds`. Each path's `lineType` selects height/speed/accel and the slicer feature label. The four gcode templates render through `_renderTemplate`, which evaluates `{...}` blocks as arithmetic over a fixed namespace via an **AST whitelist**, not `eval` — a shared/downloaded template must not be able to reach arbitrary code (`().__class__...`) or blow up via `**`/string-repeat. `createFile` renders the two machine templates first into `MACHINE_PREFIX`/`MACHINE_SUFFIX`, then renders the slicer templates (which reference those placeholders) against the same namespace — `re.sub` doesn't rescan its own replacement text, so the two sides stay mutually unaware of each other. The pen-load dwell (`WAIT_FOR_PEN`) emits `G4 P` (milliseconds) with optional `M73 P` countdown steps clamped to 1%–5% of the delay, using cumulative (not per-step) rounding so short dwells can't drift.

## Tessellation (`Path.tessellate`)

Bidirectional greedy fitter: reduces any curve to Line/Arc within tolerance, working in normalized subpath-space (0 ≤ t ≤ 1) so fits can span segment boundaries. Key behaviors:
- **Already-final segments atomic**: `Line` passthrough (unless `fitLines=True`), circular `Arc` passthrough → prformance gain.
- **Line merging**: `appendMerging` catches exact-collinear runs the fitter misses (each already fits individually).
- **`fitLines=True`** (used by infill arc-recovery): re-fits raw polygon points → arcs, with optimized fast path for all-`Line` ranges (no per-segment interior sampling).
- **Numerically unstable circumcircles rejected** via `MAX_RADIUS_TO_CHORD` guard — filters near-collinear noise.
- **`allowArcs=False`** skips the fitter entirely and flattens each segment independently via `Segment.toPoints` (base-class recursive subdivision; `Line`/`Arc` override it with an exact split). `toPoints` checks flatness at two interior points (1/3, 2/3) per recursion level, not just the midpoint — a single midpoint sample can land exactly back on the chord for a point-symmetric curve (e.g. an S-shaped cubic bezier whose inflection sits exactly at t=0.5), which would wrongly read as "flat" and collapse the whole curve to a straight line even though it bows out on both sides of that point.

## Error Handling

- **Missing/invalid config file** — `initFromMachineJson`/`initFromSlicerJson` catch a missing file and parse/type errors separately, print a one-line message, and proceed with defaults either way.
- **Invalid SVG file** — `loadSvg` re-raises any svgelements parse error, and raises its own `SvgParseError` for a missing or non-positive `viewBox` (needed to size the drawing; svgelements stores a negative viewBox as-is rather than rejecting it). `_Process.py`'s `run()` catches this around just the `loadSvg` call, re-prompts for input, and clears the cached document.
- **Empty/degenerate paths** — a `<path>` with no drawable segments is dropped in `parseSvgElement` rather than kept as a placeholder empty `Path`, since `route.py`'s ordering assumes every object has at least one segment.
- **Output retries** — `run()` caches the parsed/routed `document` in a module global. A write failure only re-prompts for the output file and redoes `createFile` against the cached document — no re-parse, no re-asking the rescale question. The cache clears only when the input file changes.
- **Output file safety** — `createFile` writes to a temp file and `os.replace()`s it over the real target only on full success, so a mid-pipeline failure leaves the existing output untouched.

## Settings (`lib/settings.py`, `config/machines/*.json`, `config/slicers/*.json`)

`Settings` (a dataclass, in `lib/settings.py` alongside the `LineType` enum it keys heights/speeds/accels/lineTypes by) is shared across the whole pipeline — `parseSvg`, `generateStroke`, `generateInfill`, `orderPaths`, and `createFile` all take a `Settings` instance and read the fields they need directly, rather than being passed individual values. `LineType` has four draw roles (`STROKE`, `INFILL`, `GAP_INFILL`, `INVALID` - the last only emitted when `processing.showOutOfBounds` is true, see Generate above) plus `TRAVEL`, `RAW_GEOMETRY` (see Geometry Model), and three bounds-debug values (`_SEGMENT_BOUNDS`/`_PATH_BOUNDS`/`_DOCUMENT_BOUNDS`, drawn only when `debug.showBoundingBoxes` is true). Those three have no `motion.heights` entry of their own in the JSON — `initFromMachineJson` derives them as `max(heights[STROKE], heights[INFILL], heights[GAP_INFILL]) + .1/.2/.3` right after loading, so the debug boxes always sit above every real draw height without needing to be kept in sync by hand; a `_segmentBounds`/`_pathBounds`/`_documentBounds` key still present under `motion.heights` in the JSON is rejected with a warning telling the user to remove it. `motion.speeds`/`motion.accels`/`visualization.lineTypes` are unaffected and may still key these three directly (`lineTypes` does, for the debug boxes' slicer-preview feature names).

**Machine vs. slicer.** Every `Settings` field is owned by exactly one of two module-level frozensets, `_MACHINE_FIELDS` or `_SLICER_FIELDS` — disjoint and together covering every field (`tests/test_settings.py`'s `testMachineAndSlicerFieldsPartitionSettings` checks this directly, so a newly added field that lands in neither set fails loudly instead of becoming silently unloadable). A **machine** config (`config/machines/<printer>.json`, currently just `bambu_p1s.json`) describes the physical printer and how the drawing should render regardless of slicer: `machine` (startPos/penOffset/plateSize/safeZoneSize/safeZoneOffset/canvasSize/canvasOffset/printerModel/maxHeight — see Alignment & Scaling below), `motion` (per-role heights/speeds/accels/shortTravelThresholds, loadDelay/showLoadProgress, eAxisMultiplier), `processing` (tessellationTolerance, penWidth, fillSpacing, machine gcode template paths), `visualization` (showPenPos, objectHeightChange, style), `debug` (showBoundingBoxes, optimizePathOrder, profiling). A **slicer** config (`config/slicers/<slicer>.json`, currently just `bambu_studio.json`) supplies only that slicer's own vocabulary for the choices the machine config already made — `visualization` (styleChangeMessage/layerChangeMessage, lineTypes/instructionTypes/segmentTypes, slicer gcode template paths) — and has no effect on where the pen actually goes. `showPenPos`/`objectHeightChange`/`style` live on the machine side even though they only affect slicer preview, because *whether* to show pen position, stagger object heights, or which style of preview coloring to use are choices about the drawing being generated, not about any one slicer's comment syntax — an average user changing which slicer they open the file in shouldn't have to go find and edit a second file just to keep those choices the same; only the literal strings a chosen `style` draws from (`lineTypes`/`instructionTypes`/`segmentTypes`) are genuinely slicer-specific, since a different slicer names its preview features differently. `eAxisMultiplier` lives on the machine side for a similar reason from the opposite direction: its only *purpose* is to satisfy a slicer's need for `E > 0`, but the multiplier itself exists to dodge the P1S firmware's own speed-planning behavior (see Hardware below), which is a machine fact. Swapping the machine config changes which printer runs the file and how its drawing is styled; swapping the slicer config changes only the literal names that styling renders as — neither swap should change where the pen actually travels.

`_Process.py` loads both: `settings.initFromMachineJson(path)` then `settings.initFromSlicerJson(path)`, in either order (both mutate the same `Settings` instance in place, and the two field sets never collide). Both are thin wrappers over a shared private `_initFromJson(self, path, allowed, otherAllowed, otherSideName)`, loaded via `commentjson` (supports `//` comments), which does the actual file read, parsing, and per-setting loop; `allowed` restricts which fields that call may write, and a field found in the *other* side's set is called out by name rather than treated as a generic typo (`"setting 'layerChangeMessage' ... belongs in the slicer config; ignoring it."`) — a genuinely unrecognized name still gets the plain "unknown setting" message. All fields are type-checked before use; on mismatch, the setting is skipped and a warning is printed. In `motion.heights`/`speeds`/`accels`/`shortTravelThresholds` (and `visualization.lineTypes`), a `"draw"` key sets all four draw roles at once; an explicit `stroke`/`infill`/`gapInfill`/`invalid` key overrides `"draw"` for just that role — this expansion happens once in `_initFromJson`, so the rest of the pipeline just indexes by concrete `LineType`. `shortTravelThresholds` is keyed by draw move `LineType` (a travel move shorter than the threshold stays pen-down) — `plot.py`'s `_penMove` looks up the upcoming (arrival) role via `lineType or LineType.STROKE`, same fallback `heights`/`speeds`/`accels` use. When the travel follows a different-role draw move, the threshold is the min of the departing and arriving roles' values, so a short hop into (or out of) a role with a tighter threshold isn't allowed to hide behind the other role's laxer one; `_DrawState.lastLineType` tracks the most recently drawn role to make this comparison. `initFromMachineJson` alone finishes with the alignment resolution and `_validate()` (which calls `_validateBounds()` — warn-and-continue, never resets to defaults, see Alignment & Scaling — and also warns if `generateGapInfill` is enabled while `fillSpacing <= 0` disables fill entirely), since every one of those checks reads only machine fields; `style` is validated inline (`case "style":`) in whichever call actually receives it, which today is `initFromMachineJson`. `fillSpacing` doubles as both the infill loop pitch and the stroke pass pitch (see Stroke above).

Positions (`endPos`, `penOffset`, `plateSize`, `safeZoneSize`, `safeZoneOffset`, `canvasSize`, `canvasOffset`) are stored as `complex`, matching how positions are represented everywhere else in the codebase — JSON's 2-element lists are converted via `complex(x, y)` in `_initFromJson`. `startPos` is the one exception, kept as a `dict[str, float]` (`{"X":.., "Y":.., "Z":..}`) since it needs a Z component and `createFile`'s per-file `_DrawState.pos` (current nozzle position) is built directly from it.

**Gcode templates.** Each side owns a prefix/suffix pair: `machinePrefixFile`/`machineSuffixFile` hold the printer's own start/end gcode (firmware resets, homing, the pen-load dwell, park moves), `slicerPrefixFile`/`slicerSuffixFile` hold the slicer's header/footer wrapper (Bambu Studio's `HEADER_BLOCK`/`CONFIG_BLOCK` comments, `; FEATURE:` markers) and reference `{MACHINE_PREFIX}`/`{MACHINE_SUFFIX}` at the point where the machine's own gcode should be nested inside them (see Generate above). Three lines inside Bambu Studio's `CONFIG_BLOCK` name machine facts under slicer key names (`printable_area`, `printable_height`, `printer_model`) and are fed from the machine config's `printerModel`/`maxHeight`/`plateSize` via the `PRINTABLE_AREA`/`PRINTABLE_HEIGHT`/`PRINTER_MODEL` template variables, rather than being hardcoded to one printer's numbers.

## Calibration (`lib/calibration.py`)

`calibrationTest` (machine-side, default `"none"`) lets a machine config swap the SVG for a **calibration sheet**: a test pattern that sweeps one physical setting (height, speed, ...) across a user-chosen range so the right value can be read off the printed paper instead of guessed. It is an alternate *source of geometry*, not an alternate program — `generateCalibration(settings)` stands in for `loadSvg`/`parseSvg` and returns an ordinary `Document`, which then goes through the same `createFile` a drawing does (and so inherits canvas clipping, out-of-bounds reporting, feature comments, the temp-file swap, and the output-file retry loop for free). `_Process.py` skips both file prompts when calibrating: there's no input to choose, and the output name is `test_<name>.gcode`. Stroke/infill are skipped because the geometry is already final rather than `RAW_GEOMETRY`, and routing because a sweep is only readable in the order it was built.

Each test is a function `Settings -> list[Pass]` registered in `CALIBRATION_TESTS` by name (the same string `calibrationTest` must hold). `calibrationEnabled(settings)` is where that value is validated — not `lib/settings.py`, which can't import the registry without a cycle. A `Pass` is one swept value: its `STROKE` geometry, optional `labelOrigin`, and the height/speed/accel it sweeps; `generateCalibration` turns each into a `PathObject` carrying those as `overrides`. A pass's label becomes its own object taking the *same* overrides (a separate dict, not the row's), so it degrades exactly when its row does — a value whose own label came out unreadable is one the sheet is already telling you not to use, and the ruler ticks are what keep a row countable when its label doesn't survive.

A sweep whose rows are one shape repeated up the page is built by `_rulerSweep`, shared by `height`/`speed`: it takes the three row shapes as a `(plain, every-5th, every-10th)` tuple in local space (baseline on y=0), deep-copies the right one per row, stacks them at `3.5 * penWidth`, labels only the 10th, and **reverses** odd rows (identical drawn shape, drawn end-to-start) so the pen finishes where the next row begins. `_lineShapes(length)` supplies that tuple for the common single-horizontal-line case; a test whose rows are something else (a zigzag) passes its own three.

**Per-object motion overrides** (`PathObject.overrides`, consumed by `lib/plot.py`) are the general mechanism this rests on: a `dict[str, float]` keyed by `_MOTION_OVERRIDES` (`height`/`speed`/`accel`), in the same units as the `Settings` fields they replace (so `speed` is mm/min, matching `settings.speeds`, not the mm/s the JSON is written in). `_addPath` copies them onto `_DrawState` so `_drawHeight`/`_drawSpeed`/`_drawAccel` can consult them without threading an argument through `_penMove`/`_emitSegment`/`_addLine`. They apply only to an object's own **draw** moves — a travel is the machine repositioning between drawn things, not something any one object asked for, so it keeps the configured travel speed/accel. Its height is the one exception: `_travelHeight` raises it 1mm above the arriving object's own height override when that override sits above the configured travel height (e.g. the `height` sheet sweeping past it) — otherwise the lift-then-move sequence would leave the XY travel happening at or below the object's own draw height. `settings.py`'s `_validate()` separately warns if a *plain* draw height (no override involved) is configured above the travel height, since that case has no override for `_travelHeight` to react to. A height override also suppresses `objectHeightChange`'s +0.001mm preview raise, which would otherwise land on half the rows of a sheet specifically sweeping height.

The stroke font (`_GLYPHS`) maps each character to a tuple of **strokes**, each an ordered run of points emitted as its own `Path`. Splitting per stroke rather than pooling a glyph's segments into one `Path` is required, not cosmetic: `Path.tessellate`'s `appendMerging` splices consecutive collinear `Line`s without checking that they touch, so two unrelated strokes that happen to be collinear (two horizontal bars at the same height) would silently fuse into one wrong line.

The specific tests, what each measures, and how to run them are documented in `README.md` for a non-technical reader — that list is not duplicated here.

## Alignment & Scaling (`lib/settings.py`, `lib/svgparse.py`)

All positions/sizes are in mm, lower-left-corner convention, and nest: **plate ⊇ safe zone ⊇ canvas**. `plateSize`'s lower-left corner is fixed at the origin — the one physical/nozzle-space rect. `safeZoneSize`/`safeZoneOffset` and `canvasSize`/`canvasOffset` are in **pen space** (where the pen tip should be), not gcode/nozzle space; `canvasSize` is the field users change to resize the paper.

`safeZoneAlignment`/`canvasAlignment` (`"BL"`/`"BR"`/`"TL"`/`"TR"`, default `"BL"`) name which plate corner the matching offset is measured from, translating toward the plate's center from there; `"BL"` is a no-op so existing configs are unaffected. `initFromMachineJson` resolves both into the plain lower-left offset the rest of the pipeline expects (`_alignedOffset`) — nothing downstream is alignment-aware.

Since the pen tip sits at `nozzle + penOffset`, a pen-space position `P` maps to nozzle position `N = P - penOffset`; `parseSvg`'s printer-space transform centers on `canvasOffset + canvasSize/2` (pen space) and only then subtracts `penOffset`.

`_validateBounds()` warns — but never alters the loaded values — on three containment checks: safe zone inside plate, canvas inside safe zone (both pen-space, direct compares), and nozzle movement (`safeZoneOffset - penOffset`) inside plate — checked separately from the safe-zone check since a safe zone that keeps the pen on the plate can still walk the nozzle off it.

`promptRescale` skips the prompt if the SVG viewport already matches `canvasSize`; otherwise it offers keep-as-is / fit-width / fit-height / stretch (the last three collapse to one option when the aspect ratios already match). The resulting scale, Y-flip, canvas-centering, and `penOffset` compensation apply as one transform matrix per object.

## Hardware

**Bambu Lab P1S**: E-axis represents pen-tip distance, not filament. `M221 Sxx` (flow rate) does work on the P1S but has an undocumented floor: below 10% the value is **silently discarded**, with no error and the extruder just continuing at its previous ratio (confirmed by direct observation across a matrix of `S` values). The prefix sends `M221 S10` — the lowest value actually honored. Separately, the firmware's speed planner throttles XY speed against the E rate as written in the gcode file, *before* `M221` is applied to the motor — so lowering `M221` alone doesn't relax that cap, and `M203 E` raises are clamped/ignored so it can't be lifted from gcode either. The real workaround is `motion.eAxisMultiplier` (0.5 in the P1S config), which scales every emitted E value (`_eValue`, in both G1 draws and G2/G3 arcs) so the *file's* E rate stays low enough that the throttle never engages; combined with `M221 S10`, actual extruder motion is a further 10x below that. Side effect: the slicer's total-filament stat scales down by the same factor.

`_eValue` collapses any non-positive multiplier to a literal `0` (which `_addLine` then elides) rather than multiplying through — a *negative* multiplier would otherwise yield a truthy negative E, writing a retraction into every draw move instead of dropping E entirely. `_validate()` warns if the multiplier is ≤ 0.

`lib/plot.py`'s `BED_EXCLUDE_AREA` (plate rect minus canvas rect, for the slicer's drawable-area render) is built by classifying which of the plate's 4 edges the canvas fails to touch, then either keyholing a ring, joining two strips, or tracing one simple polygon directly — no polygon library needed since both rects are axis-aligned. `safeZone` is not part of this polygon.

## Dependencies

`pyclipper` (infill polygon offsetting), `svgelements` (SVG parsing), `commentjson` (JSONC), `scipy` (arc-length integration; also `scipy.spatial.Voronoi` for the infill medial-axis gap fill — imported lazily there so its absence just falls back to loop gap fill). `pyclipper` has no type stubs; `typings/pyclipper/__init__.pyi` is hand-cleaned via `stubgen`.

- `lib/route.py` — path ordering (TSP-like routing)
- `lib/stroke.py` — multi-pass stroke generation, raw-geometry cleanup (`generateStroke`, `dropRawGeometry`)
- `lib/infill.py` — infill generation (tiled concentric rings + per-ring medial-axis gap fill)
- `lib/calibration.py` — calibration sheet framework (prompts, stroke font, `Pass`/`CALIBRATION_TESTS`/`generateCalibration`) and the individual tests registered into it
- `config/machines/bambu_p1s.json` — machine/motion/processing/debug config for the Bambu P1S; other printers get their own `config/machines/<printer>.json`
- `config/slicers/bambu_studio.json` — visualization config for Bambu Studio; other slicers get their own `config/slicers/<slicer>.json`
- `typings/pyclipper/__init__.pyi` — type stubs for pyclipper
- `gcode_templates/machines/bambu_p1s_{prefix,suffix}.gcode` — the P1S's own start/end gcode, referenced by the machine config's `machinePrefixFile`/`machineSuffixFile`; named per-printer like the machine configs
- `gcode_templates/slicers/bambu_studio_{prefix,suffix}.gcode` — Bambu Studio's header/footer wrapper (nests `{MACHINE_PREFIX}`/`{MACHINE_SUFFIX}` inside it), referenced by the slicer config's `slicerPrefixFile`/`slicerSuffixFile`; named per-slicer like the slicer configs
- `gcode_templates/machines/default_{prefix,suffix}.gcode`, `gcode_templates/slicers/default_{prefix,suffix}.gcode` — the `Settings` dataclass's own fallback templates, used when no config is loaded; the slicer pair is a bare `{MACHINE_PREFIX}`/`{MACHINE_SUFFIX}` pass-through with no wrapper of its own
- `*.svg` — test drawings (`horse.svg` multi-subpath; `testDrawing.svg` tests fill rules)
- `tests/` — further test SVGs: `comprehensive.svg` (one file, grouped by feature area — basic shapes, transforms, fill, stroke (including multi-pass stroke expansion cases), structure/misc, degenerate cases — every element `id`-named for what it tests, since the parser echoes that `id` when it drops/warns on an element), `viewport-*.svg` (minimal fixtures for each `promptRescale` branch), and `invalid.svg` (malformed XML, for `SvgParseError`); see `tests/README.md` for the full map
- `README.md` — non-technical usage doc (currently just how to run each calibration test) for the person operating the printer, as opposed to this file
